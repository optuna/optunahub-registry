# The `statements=` reference

`OptQuestSampler(statements=[...])` builds an OptQuest model from a list of statements. Each
statement is a dict that declares one element of the model (a decision variable, an output, a
constraint, an objective, or another model element) with the command vocabulary of the
OptQuest engine. It is the **recommended way to reach OptQuest's manifold variable types**
(DAGs, mixtures, assignments, sequences, and the rest) and its permutation variable, which
Optuna's `trial.suggest_*()` has no way to express.

```python
statements = [
    {"cmd": "CONTINUOUS", "name": "x", "min": -5.0, "max": 5.0},
    {"cmd": "DAG", "name": "flow", "nodes": ["A", "B", "C"]},
    {"cmd": "OUTPUT", "name": "cost"},
    {"cmd": "OBJECTIVE", "name": "obj", "direction": "min", "expression": "cost"},
]
```

Every dict has one required key, `"cmd"`, whose value is the command (case-insensitive on the engine
side, but written upper-case by convention). The remaining keys are that command's fields: the
same fields, in the same units, as the corresponding `OptQuestModel` method
(`model.add_continuous_variable(name, min, max)` ↔ `{"cmd": "CONTINUOUS", "name": ..., "min": ..., "max": ...}`) and the STDIO command-line protocol (`CONTINUOUS <name> <min> <max>`)
documented in the OptQuest Optimization API help. The key names are the ones in the tables
below; a few differ from the typed API's parameter names (for example `VECTOR` takes `size`, and
`PARALLELHINT` takes `threads`).

This document is the field-by-field reference for that dict shape. It also gives the value
that each variable has when it comes back to your code, in the `params` that `sim(params)`
receives from `sampler.wrap(sim)`. The OptQuest engine documentation, with the
`OptQuestModel` API and the expression language of `EXPRESSION` and `CONSTRAINT`, is at
https://www.opttek.com/documentation/.

## Command reference

Fields are listed by their dict key. A field marked `?` is optional. `name` (the variable's own
name) is required on every command that has one. The name of a variable, output or expression, and
an item, node, task or component name, must be ASCII text, a bound or an `ENUMERATION` value must be
from -2\*\*50 to 2\*\*50, and an int field must be from -2\*\*31 to 2\*\*31 - 1 (except the seed of
`RANDOMSEED`): `OptQuestSampler` raises `ValueError` for another one (see the README).

### Scalar variables

| `INTEGER`     | `name`, `min`, `max`                                                            | The values `min`, `min` + 1, `min` + 2, and so on, up to `max`. The bounds must be whole numbers: `OptQuestSampler` raises `ValueError` otherwise, because an Optuna `IntDistribution` cannot hold the values of a grid that starts at a fraction. Use `DISCRETE` with `step` 1 for that grid. The range can have at most 2\*\*31 - 1 steps: the engine counts the steps of a grid in a 32-bit int and proposes only the first 2\*\*31 values of a wider one, so `OptQuestSampler` raises `ValueError` for a wider range.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `DISCRETE`    | `name`, `min`, `max`, `step`                                                    | The values `min`, `min` + `step`, `min` + 2 × `step`, and so on. The largest value is the one nearest to `max`, so it can differ from `max` when `max` - `min` is not a whole multiple of `step`; when that value is within 1e-5 of `max`, the engine keeps `max` itself as its largest value. `step` must be greater than 0 (`OptQuestSampler` raises `ValueError` otherwise), and the grid can have at most 2\*\*31 - 1 steps, as for `INTEGER`. With `OptQuestSampler(statements=...)`, the largest value follows Optuna's rule instead: it is the `high` that `FloatDistribution(min, max, step=step)` keeps, the largest value that is not above `max` (from 0 to 1 with `step` 0.6, the values are 0 and 0.6), and the sampler gives the engine that value as `max`. With `model=`, the model is already built, so the engine's rule applies, and the sampler's distribution goes up to the engine's largest value (here 1.2). The engine takes a `min` and a `max` within 1e-5 of each other (`max` - 1e-5 < `min` in floating point) for one value, and `OptQuestSampler` raises `ValueError` for such a grid. |

The elements of these variables are ordinary input variables.

- **Variable names**: a vector has `<name>@1` to `<name>@n`, one for each element. A matrix has
  `<name>@<row>,<col>` for each element, with 1-based row and column numbers, row by row. An
  N-dimensional variable has `<name>@<i1>,<i2>,...` for each element, with one 1-based index for
  each dimension; the last index changes fastest.
- A name that contains a comma must be in brackets in an expression: `[<name>@1,2]`.
- Integer elements follow the `INTEGER` rule and discrete elements follow the `DISCRETE` rule
  above. Binary elements hold 0 or 1.

| `cmd`         | Fields                            | Notes                                                                              |
| ------------- | --------------------------------- | ---------------------------------------------------------------------------------- |
| `PERMUTATION` | `name`, `items` (list of strings) | An ordinary decision variable, not a manifold type: one 1-based position per item. |

### Manifold variables

In every solution that the engine generates, the values of a manifold variable meet the guarantee in
the Notes column. The engine can change the values in a suggested solution so that they meet the
guarantee. It uses the values of an evaluated or a required solution as given. The values of a
manifold variable are inputs, except the `POLICYSEQUENCE` outputs that the Notes column names.
`ASSIGNMENT`, `ITEMSELECTION` and `BUDGETEDSELECTION` work differently: the engine adds their rules
to the model as constraints, so a solution that breaks a rule is infeasible.

| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `MULTICHOICE`         | `name`, `choices` (list of names), `min_select`, `max_select`                                                                                                                                           | **Variable names**: `<name>@<choice>` for each choice: 1 if the choice is selected and 0 if it is not. The number of selected choices is from `min_select` to `max_select`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `MIXTURE`             | `name`, `components` (an int count or a list of names), `min`?, `max`? (give both or neither; each is a single number broadcast to every component, or a per-component list), `sum_to`? With `connected: true`, every node can be reached from `start` and every node can reach `end`; `connected` needs `start`, `end` or both. No directed path runs from a node to one of its predecessors. Every name in `predecessors` must be one of the `nodes`, written the same way: the engine ignores another name, and `OptQuestSampler(statements=...)` raises `ValueError` for it. |
| `TREE`                | `name`, `nodes` (list of names), `root`?, `predecessors`? (a dict of node → list of predecessor nodes)                                                                                                  | **Variable names**: the same as `DAG`. The edges form a directed spanning tree: one node is the root, every other node has exactly one incoming edge, and every node can be reached from the root. The tree has exactly n - 1 edges. The root is `root` when it is given, and any node otherwise. No path from the root to a predecessor passes through the node that depends on it. | `PATH`                | `name`, `nodes`, `path`? ### Smooth variables (low-rank / time-series / spline / Fourier)

These are manifold variables too. In every solution that the engine generates, every entry is
from `min` to `max`. The bounds apply to the values that the simulator receives.

| `cmd`                                                | Fields                                                                             | Notes                                                                                                                                                                                                                                                                  |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `LOWRANK`                                            | `name`, `rows`, `cols`, `rank`, `min`, `max`                                       | The matrix is the constant matrix (`min` + `max`) / 2 plus a correction of rank at most `rank`, so the matrix itself can have rank `rank` + 1.                                                                                                                         |
| `LOWRANKCORRECTION`                                  | `name`, `initial` (a matrix), `rank`, `min`, `max`                                 | The matrix is `initial` plus a correction of rank at most `rank`. The engine first moves each entry of `initial` into \[`min`, `max`\].                                                                                                                                |
| `LOWRANKINCREMENTAL`                                 | `name`, `initial`, `rank`, `min`, `max`                                            | The matrix is `initial` plus a correction of rank at most 1. `rank` is the number of this step in the sequence and does not change the values. Each variable does not keep the corrections of earlier variables: pass the best value of the previous run as `initial`. |
| `TIMESERIESVECTOR`                                   | `name`, `long_scale`, `short_scale`, `rank`, `min`, `max`                          | The engine arranges the values row by row as a `long_scale` by `short_scale` matrix. The matrix is the constant matrix (`min` + `max`) / 2 plus a correction of rank at most `rank`.                                                                                   |
| `TIMESERIESCORRECTIONVECTOR`                         | `name`, `initial` (a flat list), `long_scale`, `short_scale`, `rank`, `min`, `max` | The matrix is `initial` plus a correction of rank at most `rank`.                                                                                                                                                                                                      |
| `TIMESERIESINCREMENTALVECTOR`                        | `name`, `initial`, `long_scale`, `short_scale`, `rank`, `min`, `max`               | The matrix is `initial` plus a correction of rank at most 1. `rank` is the number of this step and does not change the values.                                                                                                                                         |
| `BSPLINEVECTOR` / `SPLINEVECTOR`                     | `name`, `length`, `num_knots`, `min`, `max`                                        | A smooth curve with `num_knots` knots at evenly spaced elements. The B-spline curve does not pass through its knots. The spline (centripetal Catmull-Rom) curve passes through its knots.                                                                              |
| `BSPLINECORRECTIONVECTOR` / `SPLINECORRECTIONVECTOR` | `name`, `initial` (a flat list), `num_knots`, `min`, `max`                         | `initial` plus a correction on the same kind of curve.                                                                                                                                                                                                                 |
| `BSPLINEMATRIX` / `SPLINEMATRIX`                     | `name`, `rows`, `cols`, `knot_rows`, `knot_cols`, `min`, `max`                     | A smooth surface with a `knot_rows` by `knot_cols` grid of knots. The B-spline surface does not pass through its knots. The spline surface passes through its knots.                                                                                                   |
| `BSPLINECORRECTIONMATRIX` / `SPLINECORRECTIONMATRIX` | `name`, `initial` (a matrix), `knot_rows`, `knot_cols`, `min`, `max`               | `initial` plus a correction on the same kind of surface.                                                                                                                                                                                                               |
| `FOURIERVECTOR`                                      | `name`, `length`, `num_freq`, `min`, `max`                                         | A sum of the `num_freq` lowest-frequency cosine terms, including the constant term.                                                                                                                                                                                    |
| `FOURIERMATRIX`                                      | `name`, `rows`, `cols`, `freq_rows`, `freq_cols`, `min`, `max`                     | A sum of the lowest-frequency cosine terms: `freq_rows` terms down the columns and `freq_cols` terms along the rows.                                                                                                                                                   |
| `FOURIERCORRECTIONVECTOR`                            | `name`, `initial` (a flat list), `num_freq`, `min`, `max`                          | `initial` plus a correction that is a sum of the `num_freq` lowest-frequency cosine terms.                                                                                                                                                                             |
| `FOURIERCORRECTIONMATRIX`                            | `name`, `initial` (a matrix), `freq_rows`, `freq_cols`, `min`, `max`               | `initial` plus a correction that is a sum of the lowest-frequency cosine terms.                                                                                                                                                                                        |

**Variable names**: the vector commands and the time-series vector commands have `<name>@1` to
`<name>@n`. For a time-series vector command, n is `long_scale` × `short_scale`, and element
i × `short_scale` + j + 1 is the entry in row i and column j of the matrix, with 0-based i and j.
The matrix commands have `<name>@<row>,<col>`, with 1-based row and column numbers, row by row.
Write a name that contains a comma in brackets in an expression: `[<name>@1,2]`. Every correction
command first moves each entry of `initial` into \[`min`, `max`\].

**`TIMESERIESCORRECTIONVECTOR`/`TIMESERIESINCREMENTALVECTOR`'s `initial` must have exactly
`long_scale * short_scale` elements.** Unlike every other correction command above (where the engine
reads the element count from the length of `initial`), the time-series vector pair has `long_scale`
and `short_scale` as separate fields that must already agree with `initial`'s length. A mismatch is
rejected up front with an error.

### Variable modifiers

These act on variables that are already declared. Declare the variables first, then the modifier. A
member of `SELECTION`, `EXCHANGE`, `FIXGROUP` or `FLOATGROUP` is the name of a scalar decision
variable, or an element of a vector, matrix, N-dimensional, permutation, item-selection or
budgeted-selection variable, such as `v@1`, `m@1,2`, `n@1,2,3` or `perm@a`. The name in `EXCLUSIVE`
is the name of a scalar decision variable or an element of a vector, matrix or N-dimensional
variable that is not binary, or a `TUPLE` or `GEOLOCATION` variable (a range of row indexes): the
sampler refuses an exclusive range on an element of a binary vector, matrix or N-dimensional
variable and of a permutation, item-selection or budgeted-selection variable, which the engine
refuses. The model check refuses any other name that holds `@`, for example the value `dir@theta` of
an angle variable or `v@4` for a vector of 3 elements. A member name can hold a comma but no
whitespace or `;`. `EXCHANGE` joins the members of a group with commas, so in an `EXCHANGE` member
each comma must be followed by a digit, as it is in every generated element name: the engine reads
`EXCHANGE g m@1,1,m@1,2;m@2,1,m@2,2` as the groups (`m@1,1`, `m@1,2`) and (`m@2,1`, `m@2,2`).

| `cmd`        | Fields                                                   | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------ | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `EXCLUSIVE`  | `name`, `min`, `max`                                     | Narrows an *already-declared* variable's domain by excluding the open sub-range `(min, max)`; not a new variable. The engine moves a value inside the range to the nearer edge, so each edge must be a value of the variable. `OptQuestSampler(statements=...)` moves an edge that the variable cannot take outward to the nearest value that it can take, which excludes the same values; with `model=`, it raises `ValueError`. Two ranges of one variable that overlap are built as one range with `statements=`, and refused with `model=`. A range that excludes a value within 1e-5 of one of its edges is refused: the engine takes such a value for the edge. On an `ENUMERATION`, an edge one rounding error away from a value, with that value inside the range, is an edge that is not a value. With `model=`, an edge can be infinite. The engine refuses an exclusive range on a `BINARY` or `DESIGN` variable. |
| `SELECTION`  | `name`, `vars` (list of already-declared variable names) | One binary flag named `name` that gates the listed variables: `1` and they participate, `0` and they are forced to their lower bound for that solution.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `EXCHANGE`   | `name`, `groups` (list of lists of variable names)       | Declares identical items, one group of variables for each item. In each generated trial solution, the optimizer puts the items in ascending order, so it does not evaluate two solutions that differ only by an exchange of items. Use it only for items with the same type, bounds and role, and put a variable in no more than one exchangeable group.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `FIXGROUP`   | `name`, `vars`                                           | After an initial part of the search, the optimizer makes one more trial solution from each new trial solution, with these variables at their values in the best solution found so far and every other variable at its new value.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `FLOATGROUP` | `name`, `vars`                                           | After an initial part of the search, the optimizer makes one more trial solution from each new trial solution, with these variables at their new values and every other variable at its value in the best solution found so far.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

### Outputs, expressions, constraints, objectives

| `cmd`                 | Fields                                              | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OUTPUT`              | `name`                                              | A scalar output the simulation/task function reports back.                                                                                                                                                                                                                                                                                                                                                                                              |
| `OUTPUTVECTOR`        | `name`, `n`                                         |                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `OUTPUTMATRIX`        | `name`, `rows`, `cols`                              |                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `OUTPUTNDVARIABLE`    | `name`, `dims`                                      |                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `EXPRESSION`          | `name`, `expression` (a string)                     | A named intermediate expression over already-declared variables/outputs.                                                                                                                                                                                                                                                                                                                                                                                |
| `CONSTRAINT`          | `name`, `expression`                                | A real OptQuest constraint: the engine will not propose a trial that violates a constraint on ordinary decision variables. | `OBJECTIVESTATISTIC`  | `name`, `statistic`, `value`                        | The per-replication statistic (mean, percentile, std-dev, ...) that the objective uses; `value` is the percentile as a fraction in `[0, 1]` when `statistic` is the percentile statistic, otherwise `0`.                                                                                                                                                                                                                                                |

- `statistic`: 0 = None, 1 = Mean, 2 = Median, 3 = Percentile, 4 = StdDev, 6 = Variance,
  8 = CoeffOfVar, 14 = Min, 15 = Max, 16 = Sum.

`FIXGROUP`/`FLOATGROUP`/`EXCHANGE`/`EXCLUSIVE`/`SELECTION` are listed under Variable modifiers above

A `LICENSE` or `RANDOMSEED` statement applies when you do not pass `license=` or `seed=` to

`OptQuestSampler` raises `NotImplementedError` for the random variable commands

noise that the engine draws,

## What comes back: decoded values

This section gives the value under `params["<name>"]` that your `sim(params)` function
(passed to `sampler.wrap(sim)`) receives for a variable declared through `statements=`.
`trial.params` holds the flat `"<name>@<key>"` values that these are decoded from.

The scalar and container commands decode to plain values: a `CONTINUOUS`/
`INTEGER` variable is a plain number, a `VECTOR` is a flat list, a `MATRIX` or `NDVARIABLE` is a
correspondingly nested list. The manifold/structured types decode as follows:

| Shape                                | Commands                                                                                                                   | Decoded value                                                                                                                                                                                                                                                 |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Bare scalar                          | `CONTINUOUS`, `INTEGER`, `DISCRETE`, `BINARY`, `ENUMERATION`                                                               | The number itself.                                                                                                                                                                                                                                            |

| 1-based index                        | `DESIGN`                                                                                                                   | A whole number from 1 to `num`. ## Outputs, objectives, and constraints

With any `OUTPUT`-family statement in the list, `sampler.wrap(sim)` expects `sim(params)` to
return a dict keyed by output name, or `None` to reject the point. A shaped output
(`OUTPUTVECTOR`/`OUTPUTMATRIX`/`OUTPUTNDVARIABLE`) takes a nested list under its key, and the
sampler flattens it to the engine's shape. A tuple or a numpy array works as a list does. A
dict or a set raises `ValueError`: a dict would be read as its keys, and a set has no order.

### Objectives must be identity pass-throughs

An `OBJECTIVE` statement's `expression` must be exactly the name of one declared `OUTPUT` (in any
case). A compound expression (`"cost * 2"`, `"cost + penalty"`) raises `NotImplementedError` when
the sampler is created, and one name that is not a declared output (a misspelled output, or the name
of an `EXPRESSION` or an input) raises `ValueError`: compute the value in `sim` and return it as an
output. `CONSTRAINT` and `EXPRESSION` take an arbitrary formula over declared variables, outputs and
expressions, except that a `CONSTRAINT` cannot name a `PERMUTATION`, `TUPLE`, `GEOLOCATION` or
`DESIGN` variable.

### Constraints

The engine checks a constraint on ordinary decision variables before the trial runs. It
checks a constraint that uses an output, or a value of a special purpose variable such as
`mix@a` or `dir@theta`, after `sim` returns, and moves the search toward feasible trials. The engine reads `<` as `<=` and `>` as `>=`, so a trial can sit exactly on the
boundary. Optuna sees only the objective values, so `study.best_trial` can be a trial that breaks a
constraint on an output or on a special purpose variable.

## Known restrictions

- **`POLICYSEQUENCE`**: only the item priority scores are inputs. The coefficient, contribution and
  confidence values are outputs that the engine computes, also for evaluated and required
  solutions. You cannot set them.
- **`EXCLUSIVE`** (a sub-range removed from the domain of a variable): Optuna has no distribution
  with a gap, so the distribution covers the full declared range. The engine keeps the values that
  it proposes out of the range by moving a value inside it to the nearer edge, so each edge must be
  a value of the variable (see the `EXCLUSIVE` row above). An edge that is not a value of the
  variable and has no value beyond it raises `ValueError` when the engine would move a value onto
  it: change the variable's `min` or `max` instead. Two ranges of one variable that overlap, also
  after their edges moved, are built as one range with `statements=`; with `model=`, the sampler
  raises `ValueError` for them, because the engine can move a value of one range into the other. For
  an `ENUMERATION`, the sampler applies this rule to every range, although the engine moves a value
  onto an edge that is not a value for some ranges only. The engine takes a value within 1e-5 of an
  edge for that edge and does not move it, so on a grid with a step of 1e-5 or less, and on an
  `ENUMERATION` with a value within 1e-5 of an edge, the sampler refuses the range. The engine
  refuses an exclusive range on a `BINARY` or `DESIGN` variable.
